## 1. The occurrence map

**Correct for every accepted whole-frame inner split**. The map sends the r-th mention of data row x to the r-th position of x in the outer `in_id`. Past the last copy it wraps. Position p of the analysis frame holds `outer_idx[p]`. So every mapped position holds the row it came from. The map is defined for every index whose row the outer `in_id` holds at least once. The containment rule (D-049) guarantees that for every whole-frame inner split that reaches a tuner. `inner_resamples_from_split()` guarantees it for a design it builds, because its indices are `outer_idx[positions]`. The map works index by index. So the length and the order of each index vector are kept. So the content, order and multiplicity of `rsample::analysis()` and of an explicit `rsample::assessment()` are kept.

Tested on the brief's fixtures. The reference is `group_vfold_cv()` built on `rsample::analysis(split)` under the same seed. On the grouped-inner design of the AC4 test, both folds and both splits give an `in_id` identical to the reference `in_id`. Each `out_id` is identical to `rsample::complement()` of that reference split. On the hand-built split `c(1L, 1L, 1L, 2:30)` the three mentions of row 1 map to positions 1, 61, 1.

Two points for the plan to state.

(a) The containment rule's known gaps (M138) pass through unchanged. The map must read indices with `as.integer()`, as `check_inner_splits()` does. Then an index of 1.5 maps as row 1, which D-109 accepts. An index that `as.integer()` coerces to `NA` has no row. The current code returns the rset unmapped in that case. The new code must keep that guard and never write an `NA` position.

(b) The entry checks read `identical(out_id, NA)` as the complement (D-111). The map must test the logical `NA` the same way, not with `all(is.na())`. `complement_within_outer()` already does.

**Exact inverse of the forward map only under a condition. Not every `nested_resamples()` design meets it.** The forward map at `R/nested-resamples.R:404-418` writes `in_id <- outer_idx[positions]`. The occurrence map returns the original position vector exactly under two conditions. Within the vector, the positions of each repeated row appear in increasing order. And each repeated row appears at most as often as the outer split holds it. Both hold for the `out_id` the forward map writes. That vector is `rsample::complement()`, ascending in positions, each copy at most once. For `in_id` both hold for designs with ascending analysis positions: `vfold_cv()`, `group_vfold_cv()` (built with `setdiff`), `rolling_origin()` and the sliding designs. They fail for designs that sample positions in random order or with replacement:

- `mc_cv()` draws `sample(n, size)`, so its `in_id` is unordered. Under the repeated outer split, `nested_resamples()` with `mc_cv(prop = 0.6, times = 1)` passed the overlap rule on 44 of 1500 seeds. A pass needs both copies of each repeated row on one side. On 41 of those 44 the occurrence map returned a position vector different from rsample's draw. For example rsample drew position 61 before position 1 for row 1, and the map returns 1 then 61.
- `bootstraps()` draws with replacement. It passed on 79 of 2000 seeds on this fixture. In one passing split, rows 1, 2, 4 and 5 were drawn 3, 4, 2 and 3 times. The outer split holds each twice. So the wrap clause fires (see Q3) and the position multiset differs from rsample's.

In every such case the rows, their order and their multiplicity are identical. `rsample::analysis()` and `rsample::assessment()` of the rebuilt split are identical to those of rsample's own split. This was tested with `identical()` on all 20 differing `mc_cv()` splits in a 600-seed run. rsample slices with `vctrs::vec_slice()`, which resets row names. tune reads a split only through those two accessors and the two index vectors (Q4). The analysis-side index vector is never read back. So the difference has no effect on results. What differs is the index vector itself and so the rset fingerprint, which nothing downstream compares. The plan states AC1 as rows, order and multiplicity, and confines the index-identity claim in AC2 to the grouped fixture. That is the right scope. The plan's work-log line "It gives the rsample indices on designs from `nested_resamples()`" is true only for the ascending-index designs. It needs that qualifier (R3).

## 2. The by-row complement

**Correct and leak-free.** The by-row complement is a set of positions of the analysis frame. Every position holds a row the outer split holds. So the set never holds an outer held-out row, whatever the inner split says. It excludes every position whose row the inner `in_id` holds. So it never assesses a row of the inner analysis set, under either copy. Tested on the hand-built fixture. Split 1 (`1:30`) assesses positions 31:60, rows 31 to 60. Split 2 (`31:60`) assesses positions 1:30 and 61:65, rows 1 to 30 with rows 1 to 5 twice. Split 3 (`c(1,1,1,2:30)`) assesses positions 31:60. None holds a row of 61 to 90 or of its own `in_id`.

Agreement with the five decisions:

- Overlap rule (D-103). On the whole frame the rule reads `in_id` as data rows. It counts no shared row for a logical `NA` `out_id` (`split_shares_rows()`, the `default && !repeats` branch). The by-row complement shares no row with `in_id` by construction. So the accepted design stays a design that scores no trained row.
- Apparent exemption (D-104). See the one defect below.
- Containment (D-049). Every assessed position holds an outer row.
- Held-out row in both sets (D-109). Refused at entry, so it never reaches the rebuild.
- `NA` rule (D-111). Only the logical `NA` is exempt at entry, and only that value gets the complement here.

**One defect in the rule as worded.** Rule 2 says "every position whose data row the inner `in_id` does not hold". That is `rsample::complement.rsplit()` read by rows. rsample dispatches `complement()` by class. `complement.apparent_split()` returns `seq_len(nrow(data))` for a logical `NA` `out_id`. The rolling-origin and sliding classes return a stored `out_id`. Take an `apparent_split` with a logical `NA` `out_id`. The plan's wording gives the empty set, because every outer row is in `in_id`. The right set is all 65 positions. On the fixture, the literal rule gives 0 positions and the dispatching rule gives 65. Such a split passes the entry checks only in one hand-built shape. It sits on the whole frame with `in_id` equal to the outer rows, class `apparent_split`, id "Apparent", beside hand-built bootstrap-class splits (`bootstrap_apparent()`). `rsample::bootstraps(apparent = TRUE)` on the whole frame has `in_id` `1:n`, and the containment rule refuses it. So the case is contrived. The fix costs nothing. Define the complement as the positions of the analysis frame whose data row lies in `rsample::complement(split)` read over the whole frame. Keep the `tryCatch` the hotfix has for a class whose complement errors. For the default method that is the plan's rule word for word. For the apparent split it honors D-104. The forward map at line 405 already uses `rsample::complement()` this way. So an apparent split from `nested_resamples()` arrives with an explicit `out_id` of all 65 positions, and the inverse recovers it exactly. (R1)

**The three rules compared.**

- rsample's own complement over the analysis frame, the positions not in the mapped `in_id`, is wrong. After the map, `in_id` `1:30` occupies positions 1:30. The positional complement is 31:65. Positions 61:65 hold rows 1 to 5, which the analysis set trained on. On the fixture, splits 1 and 3 share rows under this rule. It scores the model on rows it trained on, which D-103 forbids. A design built on the analysis set that does the same is refused by the overlap rule.
- Each row once, the hotfix rule, leaks nothing but reweights the assessment. Under it, split 2 assesses rows 1 to 30 once each. The analysis multiset the user chose holds rows 1 to 5 twice. The rule disagrees with what `nested_resamples()` writes for the same design built on the analysis frame. On the grouped fixture, one split does not train on rows 1 to 5. The forward map writes those rows twice into its explicit `out_id`. It also disagrees with `rsample::nested_cv()` on an outer split with repeats, whose inner frames carry both copies. So under the hotfix rule a hand-built whole-frame design scores differently from its `nested_resamples()` equivalent. That is the plan gate's own falsifier for rule 2.
- By copy, rule 2, treats the outer analysis multiset as the inner loop's population. Repeating a row in the outer `in_id` asks for exactly that. It is the only rule under which four shapes agree: `nested_resamples()` designs, hand-built whole-frame designs, designs built on the analysis set, and `rsample::nested_cv()`.

Rule 2 is the one to ship, stated through `rsample::complement()` (R1).

## 3. The wrap clause

**Such designs pass. So the clause is needed as defined behavior, not as a fallback.** Two routes:

- `nested_resamples()` with an inner bootstrap. The overlap rule accepts a bootstrap of the analysis frame under one condition: every repeated row has both copies drawn or neither. That happened on 79 of 2000 seeds on the fixture, near the 0.535^5 that five repeated rows predict. The forward map then writes a row as many times as its positions were drawn in total. On the fixture that reached four against two outer copies. Inner bootstraps are not refused (`refused_designs` is `loo_cv`, `apparent`, `permutations`). A refusal here rejects a design that the overlap rule accepted and that is statistically sound, a bootstrap of the analysis multiset.
- A hand-built whole-frame split whose `in_id` or explicit `out_id` repeats a row beyond the outer copies. The fixture's `c(1L, 1L, 1L, 2:30)` passes `check_nested()`. The overlap rule on the whole frame reads the default complement as rows outside `in_id`. The containment rule asks only that each row be held.

**The wrap gives the right sets.** For `in_id`, the analysis set holds each row with the multiplicity the design states, in the design's order. That is what the design read over the whole frame gives, and what tune fits on. On the analysis side the choice of copy is invisible to tune (Q4). For the explicit `out_id` that the forward map writes, wrap never fires, because the complement holds each copy at most once. A hand-built explicit `out_id` can mention a row more often than the outer holds it. There wrap produces repeated positions and so repeated `.row` values. The same split read over the whole frame gives the same repeated `.row` values. The map never adds a duplicate `.row` and removes some. An explicit `out_id` `c(1L, 1L)` reads as `.row` 1, 1 over the whole frame and as 1, 61 after the map. Recommendation: keep the clause. Say in the code comment that the inner bootstrap from `nested_resamples()` is the design that reaches it (R2). Refusing is the wrong option. It needs a new entry rule, against the constraint that D-049 and D-103 stand. And it refuses accepted inner bootstraps under this outer shape only.

## 4. What tune 2.1.0 and finetune 1.3.0 read from an inner split

Read from the deparsed namespaces of the installed packages.

- Finalization. `tune:::tune_grid_workflow()` calls `check_parameters(workflow, pset, data = resamples$splits[[1]]$data, grid_names)`. `check_parameters()` finalizes with `workflows::.fit_pre(wflow, data)$pre$mold$predictors`, the whole frame of the first split. `finetune:::tune_sim_anneal_workflow()` makes the same call itself: `tune::check_parameters(wflow = object, pset = param_info, data = resamples$splits[[1]]$data, grid_names = character(0))`. It then calls `tune::check_initial()`, which runs `tune_grid()` on the same rset. The racers reach it through the `tune::tune_grid()` they call on `restore_rset(resamples, idx)`, a row slice that keeps the rset attributes. So all four tuners finalize on the frame the first inner split carries. The choice of copy does not touch it.
- Per-resample reads. `tune:::.loop_over_all_stages()` takes `split <- resamples$splits[[1]]`. `.get_data_subsets()` reads exactly four things: `rsample::analysis(split)`, `rsample::assessment(split)`, `as.integer(split, data = "analysis")` and `as.integer(split, data = "assessment")`. `outcome_names(wflow, data = split$data)` reads column names only. The analysis-side index (`static$data$fit$ind`) is stored and never read. The only other read of `static$data$fit` is `.fit_pre(wflow, static$data$fit$data)`. In rsample 1.3.2 `as.data.frame.rsplit()` is `vctrs::vec_slice(x$data, as.integer(x, data))`. `as.integer.rsplit()` returns `in_id` for the analysis set. For the assessment set it returns `out_id`, or `complement(x)` for the logical `NA`.
- `.row`. `tune:::predict_all_types()` sets `tmp_res$.row <- .ind`, with `.ind` the assessment index. Then it runs `full_join(pred, processed_data$outcomes, by = ".row")`, and the same join for `metrics_by` columns and case weights. So `.row` is the position in the frame the split carries. After the rebuild that is the analysis frame, as it is since M54 for the non-repeated shape. Distinct positions keep that join one-to-one. That is the reason mapping by occurrence beats mapping to the first copy. `collect_predictions(summarize = TRUE)` averages by `.row` through `average_predictions()`. So two copies of one data row are averaged separately after the rebuild and together over the whole frame. This does not reach the results. nestedtune keeps `.inner_metrics` from the inner call and takes `.predictions` from the outer fit (`?nested_tune_grid`, "Kept from the outer fit").
- Racers. `tune_race_anova_workflow()` and `tune_race_win_loss_workflow()` read `.metrics` and the id columns through `collect_metrics(summarize = FALSE)` in `test_parameters_gls()`. They slice the rset with `restore_rset()`. `log_racing()` reads `labels(splits[[last]])`. finetune reads `in_id`, `out_id` or `complement()` nowhere. Its only `$data` read is `get_outcome_names()`, a column lookup on `rs$splits[[1]]$data`.
- `check_rset()` refuses by rset class (`loo_cv`, `nested_cv`, `permutations`) and checks resample weights. It reads no index.

So nothing in either package reads a split beyond the analysis set, the assessment set, the assessment index and the first split's frame. The copy matters only through `.row`. There the occurrence map is the choice that keeps the rows distinct.

## 5. The test bar

**Sufficient with `nested_tune_grid()` alone, given M54's evidence.** The change alters only the `resamples` object handed to `run_tuner()`. The single call site at `R/nested-tune-grid.R:770-800` serves every tuner. So recording that object with `record_run_tuner_resamples()` is a tuner-independent assertion of AC1 to AC3. The tuner-dependent step is that each tuner finalizes and fits on the frame it is handed. M54's AC1 pinned that for all four finalizing tuners on the non-repeated shape. Q4 adds, from the code, that the reads are the same four accessors under every tuner. A run of the repeated shape under the racers and the annealer re-tests tune and finetune internals that this change does not touch. One tuner-specific hazard exists and is already excluded. The racers' burn-in needs at least three inner resamples (`check_race_burn_in()`), and the fixtures hold two. So a registry loop needs a different fixture anyway.

The two oracles are the right pair. O1 is discriminating. `dials::grid_space_filling()` for five `min_n` points over the 65-row range [6, 32] gave 6, 12, 19, 25, 32. Over the 90-row range [9, 45] it gave 10, 17, 27, 36, 45, two of them outside [6, 32]. The grid depends on the seed. Another seed gave 9, 18, 28, 36, 44 over [9, 45]. So T3's requirement that O1 fails on the plan-commit code is the right way to pin the discrimination. O2 is sound. The grouped fixture's `in_id` is ascending, so the rebuilt rset carries the same positions as the reference. The frames are identical even where positions differ (Q1). One cheap addition is worth considering, not required. Assert `.Random.seed` unchanged across `analysis_framed_inner()`, since T2 promises it and no test holds it (R4).

## 6. AC1 to AC7

- AC1: right. The rows-order-multiplicity promise is the one the map keeps for every accepted design (Q1).
- AC2: right as scoped. The index identities hold on the grouped fixture, tested on both folds and both splits, because `group_vfold_cv()` builds an ascending `in_id`. They do not hold for an `mc_cv()` or bootstrap inner, and the AC does not claim them there. The positions 1, 61, 1 are tested.
- AC3: right in its assertions on the fixture. Wrong as a general rule for an `apparent_split` with a logical `NA` `out_id` (Q2). Restate the rule through `rsample::complement()` read over the whole frame. The fixture assertions do not change (R1).
- AC4: right. `rsample::analysis(repeated)` has 65 rows. `floor(65 * c(0.1, 0.5))` is 6 and 32. The whole frame gives 9 and 45. The grid of five lands outside [6, 32] on the whole frame (Q5).
- AC5: right. Identity of `.inner_metrics` and `.metrics` follows from identical analysis and assessment frames. Those hold on this fixture by position and in general by content (Q1).
- AC6: the grep reaches every passage that describes the frame. These are `R/nested-tune-grid.R:203-206` ("an outer split that repeats a row"), `R/nested-resamples.R:455` and `:519-526`, and DESIGN.md `:347-351`. Two passages it does not hit are for T4 to read. Both stay true and need no change. The "Reproducing one fold by hand" section at `R/nested-tune-grid.R:323-327` says `inner_resamples[[i]]` stands for the re-pointed rset, and that becomes true for this shape too. The hotfix bullet at the top of `NEWS.md` says the assessment set "holds only rows that the outer split holds". That stays true under rule 2. The new NEWS entry can extend that bullet or stand beside it. `R/nested-resamples.R:84` is about the overlap rule, not the frame.
- AC7: right.

Nothing is unsatisfiable. Nothing the IP1 change needs is missing. The RNG assertion (R4) is a hygiene addition.

## Beyond the brief

- The `nested_cv` shape under a repeated outer split is untouched by M139 and stays consistent. Take an inner design built on the analysis frame by `rsample::nested_cv()` or by hand. The overlap rule refuses it whenever it puts the two copies of a row on opposite sides (D-103 with `rows` the outer `in_id`). Most draws of `vfold_cv()` on such a frame do that. That is the correct refusal. The only analysis-frame designs that run under a repeated outer split keep each row's copies together. Rule 2 reproduces exactly those designs.
- The forward map at `R/nested-resamples.R:404-418` is where the row multiplicity exceeds the outer's, under an inner bootstrap. The comment above it says the indices are mapped and `out_id` made explicit. One more line fits: `in_id` then mentions a row more often than the outer split holds it, and the wrap clause in `analysis_framed_inner()` handles that.
- `complement_within_outer()` has the right skeleton for rule 2: `identical(out_id, NA)`, then `tryCatch(rsample::complement())`. The only change is from `held[held %in% outer_idx]`, rows each once, to `which(outer_idx %in% held)`, positions each copy.

## Recommendations

- R1 (apply): restate rule 2 and AC3. The new wording: "every position of the analysis frame whose data row lies in `rsample::complement()` of the split, read over the whole frame". Implement it as `which(outer_idx %in% held)` with the hotfix's `tryCatch`. For the default complement this is the plan's wording. For the apparent split it is correct (D-104). Nothing else changes.
- R2 (apply): keep the wrap clause. In the `analysis_framed_inner()` comment, name the inner bootstrap from `nested_resamples()` as the design that reaches it. Keep the guard that leaves the rset unmapped for an index with no position.
- R3 (apply): in the plan's work log and the code comment, say the inverse is exact in positions for designs with ascending analysis positions. For every accepted design it is exact in rows, order and multiplicity. Do not claim the rsample indices for every `nested_resamples()` design.
- R4 (consider): add one assertion that `.Random.seed` is identical before and after `analysis_framed_inner()` on the repeated fixture, since T2 promises it.
- R5 (reject): running the repeated shape under every tuner. The handoff is one call site. The tuners' reads are the four accessors M54 already pinned. The racer fixtures need a third inner resample, for no new evidence.
- R6 (reject): the hotfix rule of each row once, and rsample's positional complement over the analysis frame. The first reweights the assessment against the analysis multiset and disagrees with `nested_resamples()` on the same design. The second scores trained rows.
