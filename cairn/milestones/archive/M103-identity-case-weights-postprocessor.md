# M103: The workflow identity reads case weights and a postprocessor

**Status:** done (2026-09-17, PR #116 https://github.com/tidymodels/nestedtune/pull/116)

**Goal:** `workflow_identity()` records a workflow's case-weights column and its tailor postprocessor, so `nested_final_fit()` refuses a workflow differing in either, while a workflow with neither keeps the identity it has today.

**Outcome:** `workflow_identity()` (`R/workflow-identity.R`) appends `case_weights` (the column `workflows::add_case_weights()` files under `pre`, deparsed as written) and `postprocessor` (the tailor under `post`, as `postprocessor_identity()`: each adjustment's class and `deparse_settings()` of its arguments, in order; the tailor's derived `type`, each adjustment's `inputs`, `outputs`, `requires_fit`, `results` and `trained` unrecorded), each left out when absent, so a record saved before this change is `identical()` to the identity of the same workflow and still fits. `identity_difference()` (`R/checks.R`) routes a names-only difference at the top level to `optional_part_difference()`, which names a part present on one side only (the case weights ahead of the postprocessor) or says the comparison cannot name the part; `identity_part()` names the column, the adjustment count, an adjustment's type or one argument. `tailor` joins Suggests (D-065); the tests skip without it and use the two adjustments tailor computes itself. `tests/testthat/fixtures/branch-point-results.rds` is a record generated at `a0837b5` by `fixtures/make-branch-point-results.R`. A recipe naming the predictors alone drops the weights column's role and fails every fold, so a weighted fixture's recipe names the column. The two help pages, the NEWS bullet and DESIGN Architecture name the two parts as compared.
