# M114: The two Bayesian test files run in half their serial time

**Status:** done (2026-09-24, PR #129 https://github.com/tidymodels/nestedtune/pull/129)

**Goal:** The two heaviest Bayesian test files run in at most half their serial time with every test block's expectation count unchanged.

**Outcome:** `bayes_workflow()` and `srv_spline_workflow()` in `tests/testthat/helper-orchestration.R` name their spline columns as strings. recipes' `find_tune_id()` evaluates a bare name, fails, and formats a discarded cli message on every `tune_args()` call. That cost is 6.25 ms against 0.60 ms per call at review, in `benchmarks/recipes-tune-args-cost.R` (new). Three stand-ins in `test-nested-final-fit-identity.R` follow the record's string spelling: `ns_workflow()`, the reordered recipe and the `removed` probe. One expected message changed. The review re-ran three serial passes per tree. Medians: `test-time-series-bayes.R` 19.9 s against 52.0 s, `test-nested-tune-bayes-oracles.R` 22.1 s against 59.7 s. `benchmarks/test-blocks.R` (new) writes one row per test block. Both trees' tables are committed, and all 977 blocks match on expectation count. `Config/testthat/start-first` is re-cut. `benchmarks/test-timing-baseline.md` carries the M114 figures. The draft recipes issue is `benchmarks/recipes-tune-args-issue.md`, not posted by the user's choice.

**Decisions:** none cross-cutting. The plan chose string selectors over a lighter Gaussian-process engine, because that fitting measured under 3% of a run. The engine's candidate row was absorbed. One scope amendment added the two identity-file stand-ins.
