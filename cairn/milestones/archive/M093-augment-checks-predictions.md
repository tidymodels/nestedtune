# M093: augment() refuses saved predictions that do not match what each fold held out

**Status:** done (2026-09-14, PR #106 https://github.com/tidymodels/nestedtune/pull/106)

**Goal:** `augment()` on a nested run refuses a completed fold whose saved predictions do not hold exactly the rows that fold held out.

**Outcome:** `check_predictions_rows()` and `predictions_match_rows()` are new in `R/nested-results-collect.R`. For each completed fold, they compare the `.row` of `.predictions` with `rsample::complement()` of the split. A mismatch refuses with class `nestedtune_augment_predictions`, and the message names the fold labels. The five mismatches are a missing row, a repeated `.row`, an `NA` `.row`, a foreign row, and no `.row` column. A double `.row` with the same values is accepted. The check runs after `check_column_saved()` and `check_held_out_once()`. It runs before the name-collision refusal, `warn_partial_summary()` and the join. On a set, `for_workflow()` keeps the class and names the workflow, with no code change. A new test in `test-nested-workflow-map-readers.R` covers `compute_metrics()` on a set. It shows that `event_level` reaches each workflow, and that `NULL` uses each recorded level. The help page and the `augment()` NEWS bullet name the refusal.

**Decisions:** none. The plan gate chose a refusal over a warning with a count, as tune gives. A tune version or preprocessor that completes a fold with fewer predictions than held-out rows falsifies that choice.

**Review:** all four criteria verified. `devtools::check()` gave 0 errors, 0 warnings and 0 notes, and the six gating sweeps were clean. The history and prior-review lenses found nothing. The diff lens reported nine minor findings. Three were fixed at the gate, and each fix fails with its defect planted. The five-case loop asserts that other folds are not named. A test plants a mismatch together with a `.pred` data column. The set test asserts the `augment` call. Six were rejected with reasons. They were exact `%in%` matching, the hint that points at an edit, a dropped `.predictions` column, set-level warning order, overlapping check parts, and a repeated `complement()` call. For the dropped column, a probe showed `nestedtune_column_not_saved`. In CI, `format-suggest` failed once, until `air format` ran. `test-coverage` hit its 20-minute cap twice, the second time with every step passing. A rerun passed in 14m25s, and the cap candidate row records both hits.
