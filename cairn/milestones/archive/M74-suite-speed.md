# M74: The check suite and the help-page examples run faster without dropping an assertion

**Status:** done (2026-09-07, PR #84 https://github.com/tidymodels/nestedtune/pull/84)

**Goal:** Cut the time the check suite and the help-page examples take, with every assertion the suite makes today still made and the check step caps M72 set left in place.

**Outcome:** Every `reference_*` call site under `tests/testthat/` (18) goes through `memoised()`, and the four selection-rule blocks build one reference per configuration and apply the three rules through `reference_with_rule()`. The bayes, race and anneal rng "same seed" pairs, bayes-results' two control blocks, finalize's second grid run and final-fit-oracles' fit-and-reference pair each share one run. `test-parallel-identity.R` starts three daemon pools per run instead of 26: a shared 2-daemon pool for 18 blocks (BC9 polluting it in place as the last), a shared 3-daemon pool for the n = 3 arms of BC1, BC10, BC12 and BC13 as their own blocks, and BC3's private pool; `share_daemons()`, `shared_daemons()` (a per-pid `daemon_state_snapshot()` probe before each reuse), `daemon_rng_kinds()`, `unshare_daemons()` and `serial_run()` live in `helper-parallel.R`, the time-budget ledger re-keyed. The 23 help-page example blocks that build a run use `vfold_cv(v = 2)` outside and inside with `num_comp = 1:2` (the race page keeps inner v = 5); `benchmarks/time-examples.R` added, `benchmarks/profile-tests.R` prints counts per run. The `check-r-package` step cap is M72's 40 on devel and windows and 30 elsewhere, the yaml comment and PROFILE saying why. Measured at review, back to back: suite 593.5 s against 664.6 s (89.3%, bar 90%), 9680 pass / 0 fail / 0 skip against 9324; examples 7.8 / 13.0 s against 17.7 / 27.0 s (44–48%, bar 60%); check-step minutes on the measured head 20.3–26.6, every leg green. The CI-cap half of the original goal left at a re-cut (the check-step candidate row).

**Decisions:** a block's serial reference on a shared pool is built through `serial_run()`, which mocks `mirai_workers()` to 0 (the count D-018's `use_parallel()` reads) rather than by stopping the pool, since mirai holds one pool at a time.
