# M083: Every nested result records the workflow it ran under, and the final fit refuses any other

**Status:** done (2026-09-11, PR #97 https://github.com/tidymodels/nestedtune/pull/97)

**Goal:** Record a canonical identity of the workflow on every orchestrator's procedure record, so `nested_final_fit()` refuses a workflow other than the one the estimate was built around on every record, the `fit_resamples` one included.

**Outcome:** `workflow_identity()` (`R/workflow-identity.R`) deparses the model specification (class, engine, mode, main and engine arguments, engine arguments sorted by name under radix order) and the preprocessor (a formula, a variables selection, or a recipe as its roles and each step's type, selectors and settings, with step ids, quosure environments and the template left out). `new_procedure()` carries it as the `workflow` entry on all six orchestrators' records, on each `nested_workflow_map()` row and on the final fit's own record, never forwarded to a tuner. `check_workflow_identity()` in `R/checks.R` refuses a differing workflow with class `nestedtune_workflow_mismatch`, naming the first differing part, after the record, grid and marker checks and before any seed is drawn; `check_results_record()` refuses a record without the entry as one from an earlier version. Help pages, DESIGN Architecture and one NEWS bullet say what is compared and what is not: case weights, a postprocessor, a model argument's binding outside the workflow, and the values a function-valued step setting closes over. `test-workflow-identity.R` (33 assertions) and `test-nested-final-fit-identity.R` (157). Suite 9782/0, check 0/0/0, CI 9 pass with the non-gating coverage leg red on its known `readRDS` identity, as on main after M85.

**Decisions:** identity on all six records rather than the `fit_resamples` one alone; a deparsed fingerprint rather than the stored object (the M12 lesson, GP4); a pre-milestone result refused rather than migrated (D-041); the identity check after the grid and marker checks. At the return's amendment gate the user held AC1 and AC2 as written rather than widening them to case weights and the postprocessor (the return rule's recommendation), filing the gap as a candidate row.

**Review:** two passes, three-lens fan-out each. Pass 1: one defect return (AC2: a step setting written with braces was re-interpolated by `cli_abort()` and raised cli's own error). Fixed in the return: the brace defect, engine-argument order, a fallback for a difference the walk cannot place, an exact record read; case weights and the postprocessor filed as a candidate row and the prose narrowed. Rejected: deparse precision, an AC1 test deriving from the function it tests, the shared `workflow` name. Pass 2: eight findings; fixed at the gate: the function-valued setting disclosed on the help page, radix sort, a `quosures` setting deparsed by element, the earlier-version help shape naming the selection rule; the closure gap absorbed into the candidate row; rejected: a vector spliced into a step expression, `var_info` roles, a plugin rule id in a work-log line. Hygiene: the M60 lesson trimmed to its uncovered half (`devtools::check()` fails on the `withr::` mistake), the M77 line pruned for the byte budget, one LESSONS line added on cli's double interpolation, M82's row pruned, nothing graduated.
