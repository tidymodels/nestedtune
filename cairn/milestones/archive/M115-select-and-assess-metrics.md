# M115: The help and the guide say which metric selects and which metrics the outer loop scores

**Status:** done (2026-09-24, PR #130 https://github.com/tidymodels/nestedtune/pull/130)

**Goal:** The help and the guide tell a user how to choose each fold's candidate under one metric and report another (Stone 1974a, p. 116).

**Outcome:** `nested_tune_grid()` has its own `@param metrics`, which the Bayes, race and annealing pages inherit. Under the `"best"`, `"one_std_err"` and `"pct_loss"` rules, the first metric in the set chooses each fold's candidate. The `"desirability"` rule chooses by its goals, and grid and Bayes accept it. The Bayes, racing and annealing searches steer on the first metric. The outer loop scores every metric. A first metric other than the one read chooses under one loss and assesses under another, per Stone (1974, p. 116). `nested_fit_resamples()` has its own entry saying only that every metric is scored. The grid page has a Stone references entry, which the three sibling pages inherit through `@inherit`. A source comment at the first-metric lookup in `nested_fold_fit()` cites the `first_metric()` calls in tune 2.1.0 and finetune 1.3.0. The "Running the loop" section of `vignettes/nested-cv.Rmd` gained a paragraph and the guide a References section. A new block in `test-metrics-argument.R` replaces the block "selects under the metrics it was given". It checks `.selected` and outer `rmse` against the reference loop under two rules. It asserts that `metric_set(rmse, mae)` moves a fold's choice. A planted second-metric lookup failed 8 of its 23 checks. The API is unchanged. One NEWS entry.

**Decisions:** none cross-cutting. The plan chose documenting the set's order over a `metric` argument on `selection_rule()` and over a second assessment set. The implement gate chose the user-facing citation form "Stone (1974)", reading the criteria's "1974a" as naming that source.
