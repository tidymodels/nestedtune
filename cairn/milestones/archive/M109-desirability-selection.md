# M109: Selecting each fold's candidate by desirability over several metrics

**Status:** done (2026-09-22, PR #124 https://github.com/tidymodels/nestedtune/pull/124)

**Goal:** `selection_rule("desirability", ...)` selects each fold's candidate, and the final fit's, with desirability2's joint desirability over several metrics.

**Outcome:** `selection_rule()` takes a fourth rule, `"desirability"`, with goals such as `maximize()`, `minimize()` and `target()`. It captures them as expressions and runs them through `desirability2::desirability()` at build. `apply_selection_rule()` selects with `select_best_desirability()` for the folds and the final fit. `nested_tune_grid()` and `nested_tune_bayes()` check at entry that a goal's first argument names a metric of the run or a tuned parameter. The racing tuners and `nested_tune_sim_anneal()` refuse the rule through a `desirability` field in `tuner_registry`. Grid and Bayesian refuse it on a censored regression model. `selection_rule()` refuses a name in a goal's later arguments, with a `!!` hint that injects the whole argument. The constructor, the orchestrators and `nested_final_fit()` refuse the rule by class where desirability2 is absent, and `needed_pkgs()` asks daemons for it. `print()` shows each goal in full. Oracle tests compare each fold's pick and the final fit's pick with `select_best_desirability()` on the reference inner run.

**Decisions:** D-072 (desirability2 >= 0.2.0 in Suggests), D-073 (the fourth rule, superseding D-056's rule clause).
