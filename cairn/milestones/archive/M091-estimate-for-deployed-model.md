# M091: The docs give the nested estimate as the number to report for the deployed model

**Status:** done (2026-09-13, PR #104 https://github.com/tidymodels/nestedtune/pull/104)

**Goal:** The README, the four guides, the final-fit help pages and the final-fit print method state the nested estimate as the number to report for the deployed model, with the procedure-not-model principle given as the reason for that number and not as a disclaimer.

**Outcome:** README.Rmd and `vignettes/estimate.Rmd` open with three facts: a tuned winner scored once on a test set is one number from one split, the outer folds give the mean and how far the score moves, and each outer fold tunes on its own. estimate.Rmd and nested-cv.Rmd each carry one paragraph saying the estimate describes the tune-and-fit procedure, is the number to report for the deployed model, and needs no second number because that model is the same procedure run on all the data. estimate.Rmd's "Four things it is not" list became a scope paragraph. results.Rmd and tuners.Rmd name the number to report at their first mention of the deployed model, and tuners.Rmd limits a set member's rows to a workflow chosen before seeing the estimates. The print and `summary()` of a `nested_final_fit` show one constant, `final_fit_estimate_msg`. Seven help pages were reworded, including `?summary.nested_final_fit`'s reason for keeping `estimate = NULL` and `?predict.nested_final_fit`'s pointer. Tests match both facts of the message on the tuned, summary and no-tuning paths. IP3's text is unchanged.

**Decisions:** none. The plan gate chose the paired framing (one test split against several outer folds, tied to each fold tuning on its own) over the split contrast alone, and put the help pages and print in scope at the user's choice.

**Review:** three passes. Pass 1 returned the milestone on AC3, AC4 and AC6, and AC1 took an amendment for the README list item. Pass 2 returned it on AC6, because `?print.nested_final_fit` did not name `collect_metrics()`. Pass 3 passed every criterion with a fresh reader report and three-lens review. Fixed at the pass-3 gate: the dangling reason in `?summary.nested_final_fit`, "The estimate above" in the write-up template, the dropped "made on the same scores", "outer splits" against "outer fold", and two missing test matches. Follow-up: a candidate row for the `nested_results` summary note, plot subtitles and sibling tuner help pages that still say "not a model you can deploy" or "reported for the procedure". The tall-data reader note went to DESIGN.md Known issues. Pass-2 finding 20 (stale NEWS bullets) is on the `[low]` NEWS row. No lesson added or retired. CI green on fourteen checks.
