# M116: The summaries and the final fit's print name the metric that selects

**Status:** done (2026-09-24, PR #131 https://github.com/tidymodels/nestedtune/pull/131)

**Goal:** The summaries and the final fit's print name the metric that chose each fold's candidate, and the help of `nested_workflow_map()` says which metric selects.

**Outcome:** The procedure record holds `first_metric`, the first metric tune's `check_metrics_arg()` resolves for the workflow. It is resolved at the top of `nested_loop()`, before the seed draw, for every selecting tuner under every rule. The final fit records the name from its own run. `procedure_tuner()` treats the entry as shared, and a `nested_fit_resamples()` record has none. `print_selected_by()` prints `Selecting metric: <name>` after `Selected by:` under the `"best"`, `"one_std_err"` and `"pct_loss"` rules. Four surfaces show it: the results summary, each tuned section of the set summary, and the final fit's print and summary. It is absent under `"desirability"`, on fit_resamples, and on a record without the entry. Both summaries carry a `first_metric` component. The new `check_metrics_mode()` refuses a set that tune cannot resolve for the mode, before any fold runs. Its class is `nestedtune_metrics_mode`. `nested_workflow_map()` makes the same refusal in its pre-check, before any workflow runs. It skips workflows routed to fit_resamples. Help on six pages, one NEWS entry, and the new `test-selection-metric.R`.

**Decisions:** D-081 records the entry, the refusal, and the line under the default rule. That line supersedes M098's choice for the default rule. The plan chose a separate line over `best on rmse`, and recording at entry over reading at print time. The implement gate chose an entry refusal over a `tryCatch` to `NULL`.

**Review:** Two defect returns, then pass 3. Pass 1 found that AC2 lacked the set's no-entry absence test. Pass 2 found a whole run aborting on a set for the wrong mode, because the name was resolved after the loop. `main` returned the failed folds instead, and T4 fixed it. In pass 3, the blame and prior-review lenses found nothing, and the diff lens found no defect. Fixed at the gate: the refusal header, and the map help's error-timing section. Follow-up: a candidate row for a fit_resamples refusal. Four findings were rejected. They were the `NULL` default in `new_procedure()` and the entry recorded under desirability. The censored line without an evaluation time and refusal tests on grid alone were also rejected. CI caught one `air` format line. It also caught the hard leg's missing `workflowsets` skip, which LESSONS already warns about. No lesson was added, because `LESSONS.md` sits at 19,998 of 20,000 bytes.
