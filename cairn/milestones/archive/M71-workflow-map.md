# M71: `nested_workflow_map()` runs a `workflow_set` through one nested design, and the readers stack each workflow's results under its id

**Status:** done (2026-09-06, PR #81 https://github.com/tidymodels/nestedtune/pull/81)

**Goal:** Score every workflow of a `workflow_set` on the same outer folds of one nested design in one call, so the comparison a user makes across model families reads off one object with the workflow id beside the fold labels.

**Outcome:** `nested_workflow_map(object, fn = "nested_tune_grid", ...)` in `R/nested-workflow-map.R` runs each workflow of the set in order through the orchestrator `fn` names, a workflow with no `tune()` marker routed to `nested_fit_resamples()` (`route_workflow()`, `tuned_parameter_ids()`); `map_args()` merges the set's `option` entry over `...` and narrows to the routed orchestrator's formals, a `...` `control` dropped on a rerouted workflow; `run_orchestrator()` evaluates a `call2()` binding each argument to a name; `for_workflow()`/`resignal_for_workflow()` re-signal a failed-fold warning or an error with the `wflow_id` in front. `restore_map_rng()` reinstates the entry state before each workflow so every workflow's fold `i` runs under the same two seeds, a never-drew session initialized and cleaned up again. Entry checks in `R/checks.R`: `check_workflow_set()`, `check_map_fn()`, `check_map_dots()`, `check_map_options()` (`nestedtune_bad_workflow_set`, `_bad_fn`, `_bad_dots`, `_bad_option`), plus `check_workflow()`, `check_workflow_pkgs()` and, under `fn = "nested_fit_resamples"`, `check_tuned_workflow()` per element naming the id, all before the first fold. `nested_results_set` (`R/nested-results-set.R`): a tibble of `wflow_id`, `workflow`, `result` with `fn` as an attribute; `stack_set()` binds each reader's table under `wflow_id` (`vec_rbind()`), leaves out an all-failed element with one `nestedtune_partial_summary` warning, refuses a set with no completed fold (`nestedtune_no_completed_folds`), `collect_notes()` stacking everything; the six `collect_*` methods, `print()` (orchestrator label, workflow count, per-row completed-of-attempted), `extract_workflow(x, id, ...)` over `match_set_id()` (`nestedtune_unknown_id`). `nested_final_fit(object, results, ..., id = NULL)` takes a set and an `id` (`check_final_fit_set_args()`, `nestedtune_bad_final_fit_args`); `rank_results()` and `fit_best()` error on the set. `workflowsets` in Suggests (D-058). Fixtures `wset_two()`, `wset_fixed()`, `wset_three()`, `wset_results(fn)` in `helper-orchestration.R`; oracle, RNG, readers, checks and final-fit test files; BC17 in `test-parallel-identity.R`. Help pages, pkgdown rows, NEWS, DESIGN Function Families and Architecture, a `tuners.Rmd` set section and an `estimate.Rmd` paragraph on why the set carries no ranking method.

**Decisions:** milestone-local, three. A `control` in `...` reaches only the workflows run through `fn`; a rerouted workflow takes a control from its `option` entry alone (a control's class is the contract, D-042). A condition raised inside one workflow's run or reader is re-signalled with the `wflow_id` in front under its own class, naming the map or the reader as call; other classes pass through. In a never-drew session the map initializes the generator, reinstates that state per workflow, and removes it on exit with the kind restored. Observed: `workflowsets::option_add()` refuses an `object` entry; a default argument forced after `set.seed()` keyed the fixture set's recipe ids to the data seed (`force(data)`).
