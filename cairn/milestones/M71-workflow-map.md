# M71: `nested_workflow_map()` runs a `workflow_set` through one nested design, and the readers stack each workflow's results under its id

- **Status:** in-progress
- **Priority:** normal
- **Depends on:** —
- **Driving RR:** —
- **Principles touched:** IP2, IP3, IP4, GP1, GP3
- **Resolves:** —
- **Surface tier:** user-facing — a new exported orchestrator over workflow sets, a new results class, and reader methods on it
- **Branch/PR:** `m071-workflow-map`

## Goal

Score every workflow of a `workflow_set` on the same outer folds of one nested design in one call, so the comparison a user makes across model families reads off one object with the workflow id beside the fold labels.

## Scope

**In:** `nested_workflow_map(object, fn = "nested_tune_grid", ...)`, shaped like `workflowsets::workflow_map()`, taking a `workflow_set` and the name of one of the six orchestrators, running each workflow in order with the arguments in `...` merged with that workflow's `option` entry, an unmarked workflow routed to `nested_fit_resamples()` (D-057's path) with the arguments narrowed to that orchestrator's formals, and the generator state preserved between workflows so each runs under the same per-fold seeds; a standalone `nested_results_set` class (D-010's rule) holding `wflow_id`, `workflow` and `result` per row; the six `collect_*` readers stacking the per-element tables under `wflow_id`; `print()`; `extract_workflow(x, id)`; `nested_final_fit(object, results, ..., id = NULL)` reading the workflow and its record from the set; entry refusals; `workflowsets` in Suggests, called by no package code (D-058); help, pkgdown, NEWS, DESIGN, a `tuners.Rmd` section and an `estimate.Rmd` paragraph on selection across a set. Lineage: the "`workflow_set` through one nested design" candidate row added 2026-09-06 at M68's plan gate.

**Out:** one `nested_results` with a `wflow_id` column (rewrites the class, every pooled reader and the procedure record; rejected at the gate, see the work log); `summary()`, `autoplot()` and `agreement()` on the set — a candidate row; dispatching workflow-by-fold units in one parallel round — a candidate row; a ranking or best-workflow fit over the set — deliberately absent, the `estimate.Rmd` paragraph says why (IP3); a different tuner per workflow — two calls; the final fit tying a fixed workflow to a no-tuning record on the single-workflow path — the M70 review candidate row stands.

## Acceptance criteria

- [ ] AC1: `nested_workflow_map(object, fn = "nested_tune_grid", ...)` in `R/nested-workflow-map.R` takes a `workflow_set` and the name of one of the six orchestrators, runs every workflow of the set in order through that orchestrator with the arguments in `...` (a workflow with no `tune()` marker through `nested_fit_resamples()` instead, whatever `fn` names), a per-workflow entry of the set's `option` column overriding the same-named argument in `...` and, for each workflow, the arguments narrowed to what the orchestrator it routes to accepts: its formals other than `object`, and the `control` it takes through `...`; and returns a `nested_results_set`, a tibble of class `c("nested_results_set", "tbl_df", "tbl", "data.frame")` with columns `wflow_id`, `workflow` and `result`, one row per workflow in the set's order, carrying `fn` as an attribute. The generator state the map holds once its entry checks have run (the caller's, or the state a session that never drew initializes then) is reinstated before each workflow, so every workflow's fold `i` runs under the same two seeds. For every row, `result[[i]]` is `identical()` to the orchestrator that ran called by hand on `workflow[[i]]` with the same arguments after `set.seed()` of the same value, asserted in `test-nested-workflow-map-oracles.R` on a two-workflow set (one tuned, one fixed) for each of the five tuning `fn` values (the racers and the annealer under their existing skip guards, each with a `control` in `...`), on a two-workflow set of fixed workflows for `fn = "nested_fit_resamples"`, and on the three-workflow fixture for `fn = "nested_tune_grid"` with a per-workflow `grid` option on one tuned workflow.
- [ ] AC2: A `nested_workflow_map()` call leaves the caller's RNG state as it found it (`.Random.seed` identical before and after, and `exists(".Random.seed")` unchanged in a session that never drew), and for `fn = "nested_tune_grid"` on a fixture in which every fold completes, a run under two mirai daemons is `identical()` to the serial run under the same seed, as BC17 in `test-parallel-identity.R` with its row in the `helper-time-budget.R` ledger.
- [ ] AC3: `collect_metrics()`, `collect_selections()`, `collect_inner_metrics()`, `collect_notes()`, `collect_predictions()` and `collect_extracts()` on a `nested_results_set` return the same reader's table for each element row-bound in set order (the fixtures' set order differing from their `wflow_id` sort order) with `wflow_id` as the first column, `summarize = FALSE` on the first placing it before the fold label columns, equal to `dplyr::bind_rows()` of the per-element tables keyed by `wflow_id` (an element whose table has no rows contributes none); for each of the five readers other than `collect_notes()`, an element in which no outer fold completed is left out while another element completed one, with one warning of class `nestedtune_partial_summary` naming its `wflow_id`, an element that only partly completed raises that reader's `nestedtune_partial_summary` warning once with its `wflow_id` named in the message, and a set in which no element completed a fold is refused with `nestedtune_no_completed_folds`; `collect_predictions()` and `collect_extracts()`, after that refusal, refuse a set in which an element that would contribute rows did not keep the column, with `nestedtune_column_not_saved` naming its `wflow_id`; `collect_notes()` stacks every element, one in which no outer fold completed included, and refuses no set on that ground; and each of the six methods refuses a stray argument in `...` before any other check. Every clause but the last is asserted for each reader it names in `test-nested-workflow-map-readers.R`; the dots clause is the `test-dots-barrier.R` registry probe.
- [ ] AC4: `print()` on a `nested_results_set` names the orchestrator label, the number of workflows, and per row the `wflow_id` with its completed and attempted fold counts (snapshot in `test-nested-workflow-map-readers.R`); `extract_workflow(x, id, ...)` returns the element's workflow; `workflowsets::rank_results()` and `tune::fit_best()` on the set raise an error rather than returning a table or a fit; and `nested_final_fit(object, results, ..., id = NULL)` given a `nested_results_set` as `object`, `results` missing and `id` naming one `wflow_id`, returns a fit whose `$selected`, `$tuning_seed`, `$fit_seed` and `predict()` on the fixture rows are `identical()` to those of `nested_final_fit(extract_workflow(x, id), x$result[[i]])` after `set.seed()` of the same value; an `id` naming no row is refused with `nestedtune_unknown_id`, and a set given with `results` supplied, or `id` given with a workflow as `object`, with `nestedtune_bad_final_fit_args`. Asserted in `test-nested-final-fit-set.R`.
- [ ] AC5: Entry refusals, each asserted in `test-nested-workflow-map-checks.R` by condition class where one is named and each raised before any fold runs: `object` not a `workflow_set`, or one lacking the `wflow_id`, `info`, `option` or `result` column (`nestedtune_bad_workflow_set`); `fn` not one of the six orchestrator names (`nestedtune_bad_fn`); a name in `...` that is neither `control` nor a formal of the orchestrator `fn` names other than `object`, an `object` or an unnamed argument in `...`, or `...` carrying no `resamples` (`nestedtune_bad_dots`); an `option` entry named neither `control` nor a formal of the orchestrator its workflow routes to, or named `object` or `resamples` (`nestedtune_bad_option`, naming the `wflow_id`; asserted both for a name a workflow routed to `nested_fit_resamples()` cannot take and for an `object` or `resamples` entry); a fitted workflow in the set (`check_workflow()`'s refusal, asserted by its message naming the `wflow_id`); a workflow carrying a `tune()` marker in a set run with `fn = "nested_fit_resamples"` (`nestedtune_tuned_workflow`, naming its `wflow_id`); and every workflow's packages checked at entry through `check_workflow_pkgs()` (its existing class, naming the `wflow_id`).
- [ ] AC6: A help page for `nested_workflow_map()` documenting each argument, the routing of an unmarked workflow, the seeding rule and the per-workflow `option` override; the set's behaviour on the six reader pages, on `extract_workflow`'s and on `nested_final_fit`'s; a pkgdown reference row; a NEWS entry; DESIGN Function Families and Architecture paragraphs; a section in `tuners.Rmd` running a baseline and two tuned workflows through one design and reading `collect_metrics()`; and a paragraph in `estimate.Rmd` stating that choosing among a set's workflows by their nested estimates is a selection the outer loop did not nest, so the chosen workflow's estimate is not an estimate of choosing the best of them, which is why the package registers no ranking or best-workflow method for the set; `devtools::check()` reports 0 errors, 0 warnings, 0 notes, and both pages render after installing the branch.
