# M71: `nested_workflow_map()` runs a `workflow_set` through one nested design, and the readers stack each workflow's results under its id

## Goal

Score every workflow of a `workflow_set` on the same outer folds of one nested design in one call, so the comparison a user makes across model families reads off one object with the workflow id beside the fold labels.

## Scope

**In:** `nested_workflow_map(object, fn = "nested_tune_grid", ...)`, shaped like `workflowsets::workflow_map()`, taking a `workflow_set` and the name of one of the six orchestrators, running each workflow in order with the arguments in `...` merged with that workflow's `option` entry, an unmarked workflow routed to `nested_fit_resamples()` (D-057's path) with the arguments narrowed to that orchestrator's formals, and the generator state preserved between workflows so each runs under the same per-fold seeds; a standalone `nested_results_set` class (D-010's rule) holding `wflow_id`, `workflow` and `result` per row; the six `collect_*` readers stacking the per-element tables under `wflow_id`; `print()`; `extract_workflow(x, id)`; `nested_final_fit(object, results, ..., id = NULL)` reading the workflow and its record from the set; entry refusals; `workflowsets` in Suggests, called by no package code (D-058); help, pkgdown, NEWS, DESIGN, a `tuners.Rmd` section and an `estimate.Rmd` paragraph on selection across a set. Lineage: the "`workflow_set` through one nested design" candidate row added 2026-09-06 at M68's plan gate.

**Out:** one `nested_results` with a `wflow_id` column (rewrites the class, every pooled reader and the procedure record; rejected at the gate, see the work log); `summary()`, `autoplot()` and `agreement()` on the set — a candidate row; dispatching workflow-by-fold units in one parallel round — a candidate row; a ranking or best-workflow fit over the set — deliberately absent, the `estimate.Rmd` paragraph says why (IP3); a different tuner per workflow — two calls; the final fit tying a fixed workflow to a no-tuning record on the single-workflow path — the M70 review candidate row stands.

## Acceptance criteria

- [ ] AC1: `nested_workflow_map(object, fn = "nested_tune_grid", ...)` in `R/nested-workflow-map.R` takes a `workflow_set` and the name of one of the six orchestrators, runs every workflow of the set in order through that orchestrator with the arguments in `...` (a workflow with no `tune()` marker through `nested_fit_resamples()` instead, whatever `fn` names), a per-workflow entry of the set's `option` column overriding the same-named argument in `...` and, for each workflow, the arguments narrowed to the formals of the orchestrator it routes to; and returns a `nested_results_set`, a tibble of class `c("nested_results_set", "tbl_df", "tbl", "data.frame")` with columns `wflow_id`, `workflow` and `result`, one row per workflow in the set's order, carrying `fn` as an attribute. The generator state is preserved between workflows, so every workflow's fold `i` runs under the same two seeds. For every row, `result[[i]]` is `identical()` to the orchestrator that ran called by hand on `workflow[[i]]` with the same arguments after `set.seed()` of the same value, asserted in `test-nested-workflow-map-oracles.R` on a two-workflow set (one tuned, one fixed) for each of the six `fn` values (the racers and the annealer under their existing skip guards), and on the three-workflow fixture for `fn = "nested_tune_grid"` with a per-workflow `grid` option on one tuned workflow.
- [ ] AC2: A `nested_workflow_map()` call leaves the caller's RNG state as it found it (`.Random.seed` identical before and after, and `exists(".Random.seed")` unchanged in a session that never drew), and for `fn = "nested_tune_grid"` on a fixture in which every fold completes, a run under two mirai daemons is `identical()` to the serial run under the same seed, as BC17 in `test-parallel-identity.R` with its row in the `helper-time-budget.R` ledger.
- [ ] AC3: `collect_metrics()`, `collect_selections()`, `collect_inner_metrics()`, `collect_notes()`, `collect_predictions()` and `collect_extracts()` on a `nested_results_set` return the same reader's table for each element row-bound in set order with `wflow_id` as the first column, `summarize = FALSE` on the first placing it before the fold label columns, equal to `dplyr::bind_rows()` of the per-element tables keyed by `wflow_id` (an element whose table has no rows contributes none); an element in which no outer fold completed is left out while another element completed one, a set in which no element completed a fold is refused with `nestedtune_no_completed_folds`, and each of the six methods refuses a stray argument in `...` before any other check (the `test-dots-barrier.R` registry probe). Asserted in `test-nested-workflow-map-readers.R`.
- [ ] AC4: `print()` on a `nested_results_set` names the orchestrator label, the number of workflows, and per row the `wflow_id` with its completed and attempted fold counts (snapshot in `test-nested-workflow-map-readers.R`); `extract_workflow(x, id, ...)` returns the element's workflow; `workflowsets::rank_results()` and `tune::fit_best()` on the set raise an error rather than returning a table or a fit; and `nested_final_fit(object, results, ..., id = NULL)` given a `nested_results_set` as `object`, `results` missing and `id` naming one `wflow_id`, returns a fit whose `$selected`, `$tuning_seed`, `$fit_seed` and `predict()` on the fixture rows are `identical()` to those of `nested_final_fit(extract_workflow(x, id), x$result[[i]])` after `set.seed()` of the same value; an `id` naming no row is refused with `nestedtune_unknown_id`, and a set given with `results` supplied, or `id` given with a workflow as `object`, with `nestedtune_bad_final_fit_args`. Asserted in `test-nested-final-fit-set.R`.
- [ ] AC5: Entry refusals, each asserted by condition class in `test-nested-workflow-map-checks.R` and each raised before any fold runs: `object` not a `workflow_set` (`nestedtune_bad_workflow_set`); `fn` not one of the six orchestrator names (`nestedtune_bad_fn`); an `option` entry whose name is not a formal of the orchestrator its workflow routes to (`nestedtune_bad_option`, naming the `wflow_id`); a workflow of the set that `check_workflow()` refuses, the message naming its `wflow_id` (the existing classes); and every workflow's packages checked at entry through `check_workflow_pkgs()` (its existing class).
- [ ] AC6: A help page for `nested_workflow_map()` documenting each argument, the routing of an unmarked workflow, the seeding rule and the per-workflow `option` override; the set's behaviour on the six reader pages, on `extract_workflow`'s and on `nested_final_fit`'s; a pkgdown reference row; a NEWS entry; DESIGN Function Families and Architecture paragraphs; a section in `tuners.Rmd` running a baseline and two tuned workflows through one design and reading `collect_metrics()`; and a paragraph in `estimate.Rmd` stating that choosing among a set's workflows by their nested estimates is a selection the outer loop did not nest, so the chosen workflow's estimate is not an estimate of choosing the best of them, which is why the package registers no ranking or best-workflow method for the set; `devtools::check()` reports 0 errors, 0 warnings, 0 notes, and both pages render after installing the branch.

Investigation by five [S] Explore subagents (orchestrator core, results class and readers, final fit and extracts, fixtures and doc surface, workflowsets API) with file:line citations; the `procedure` record, the tuner description and the results class carry no workflow, every pooled reader assumes one, and workflowsets imports tune with no reverse edge.
- 2026-09-06: criteria audit ran in full mode ([O] fresh reader): 7 findings, all fixed before the gate — arguments narrowed to the routed orchestrator's formals; the seeding rule stated and the identity oracle covering all six `fn`; readers promising `wflow_id` only for elements contributing rows; BC17 scoped to the grid orchestrator on a clean fixture; `extract_workflow` taking `id` ahead of `...`; the no-ranking claim turned into an error probe and the vignette's claim bounded to the registered methods.
- 2026-09-06: plan gate chose a standalone set of per-workflow results over one `nested_results` carrying a `wflow_id` column because the class, the procedure record and every pooled reader assume one workflow and the row's stacking need is met by `collect_metrics(summarize = FALSE)`; falsified by a reader a user needs that the per-element stacking cannot express, such as an estimate pooled across workflows.
- 2026-09-06: plan gate chose routing an unmarked workflow to `nested_fit_resamples()` over refusing a mixed set because a baseline beside tuned models on the same folds is the comparison the set exists for and the element's record names the procedure that ran (IP4); falsified by a user surprised that a named tuner did not run on one workflow.
- 2026-09-06: plan gate chose the same per-fold seeds for every workflow over distinct seeds per workflow because it mirrors `workflow_map()`'s single seed, pairs the comparison on seeds, and makes each element identical to a hand call; falsified by evidence that shared seeds correlate the workflows' estimates in a way a user's comparison must not carry.
- 2026-09-06: plan gate chose an `id` argument on `nested_final_fit()` over hand extraction because the set holds the workflow and its record together, so the wrong pairing cannot happen; falsified by a caller needing a final fit from a set with a workflow the set does not hold.
- 2026-09-06: plan gate chose `workflowsets` in Suggests over Imports because the package reads the set's columns and calls no workflowsets function; falsified by a validator or extractor of the set the package must call at run time.
